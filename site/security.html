Security Boundary

This build uses VS Code's extension API and contribution points. Stylesmith does not patch the VS Code installation, and only writes to it once, to remove changes made by Stylesmith 1.x.

What Stylesmith does

  • Registers color themes and file icon themes through the extension manifest.
  • Uses the diagnostics and editor decoration APIs to display Problem Lens.
  • Changes global user settings through VS Code's configuration API and restores managed settings when disabled.
  • Stores managed-setting state in its own extension storage.
  • Installs a font only when you ask and confirm: the files come from this project’s release, must match a SHA-256 built into Stylesmith, and go to your own font folder, without administrator rights.
  • Does not load workspace-provided or remote CSS or JavaScript, and does not inspect workspace content to choose code to run.

What this boundary means

Stylesmith runs as a local VS Code extension and has the ordinary capabilities granted to extensions. API-only means it does not bypass VS Code's extension model to alter the workbench DOM or installed application files. It is not a guarantee that extension code or its supply chain is risk-free.

Upgrading from an older release

Stylesmith 1.x could patch the workbench and install font files beside it. On first start, this build removes exactly those changes: Stylesmith's marked blocks in the workbench file, its font folder, and a product.json checksum it had changed. It leaves other tools' changes alone and never asks for administrator rights. If VS Code is installed where your user can't write, it tells you once; repair or reinstall VS Code to restore its files.

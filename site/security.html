Security Model

Modifying your editor's core files sounds terrifying. It should be. Here is exactly how Stylesmith patches VS Code without blowing a hole in your machine's defenses.

Content Security Policy (CSP)

The Risk: Disabling or blindly relaxing VS Code's Content Security Policy allows any malicious extension or untrusted workspace to execute arbitrary, dangerous scripts inside your editor context.

The Fix: Stylesmith injects extremely narrow, surgical CSP headers. It only permits its own static assets (like bundled fonts) and local CSS to load. It never uses unsafe-eval or opens broad script execution vectors.

Why it matters: You get a heavily customized UI without opening a backdoor into your local development environment.

The Checksum Lock

The Risk: VS Code constantly monitors its own installation files. If malware modifies your editor, VS Code displays a "corrupt installation" warning. Other UI-patching extensions completely disable this warning, blinding you to actual threats.

The Fix: Stylesmith recalculates the exact cryptographic checksum of the core HTML file after making its own benign modifications, and updates the editor's lockfile to match the new hash.

Why it matters: VS Code's integrity check stays fully active. If a virus or rogue tool alters your files later, the checksum will break and you will still be warned.

Failsafe Architecture

The Risk: VS Code updates frequently. Aggressive, hard-coded UI patches can easily crash the editor, leaving you locked out of your workspace after a Tuesday morning update.

The Fix: Stylesmith's patches are structural and non-destructive. If an update breaks the CSS hooks, the modifications gracefully fail.

Why it matters: Zero downtime. Your editor will never refuse to boot because of a theme.

Workspace Immunity

The Risk: Extensions that globally modify UI styles often leak into embedded webviews (like Markdown previews or third-party extension pages), horribly breaking their layout.

The Fix: Stylesmith strictly scopes all visual modifications to the main workbench container.

Why it matters: Your code, extension menus, and previews look exactly as their authors intended, with zero visual artifacts.
